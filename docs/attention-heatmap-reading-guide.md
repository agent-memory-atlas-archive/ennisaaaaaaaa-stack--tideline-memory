# 注意力热图阅读说明

> 适用：`memory_attention_heatmap` 工具的输出报告。读者：agent 自己、人类用户、Portalk 未来的用户。
> 一句话定位：**热图量的是灯，不是房间**——它记录"什么被问过"，不判断"什么重要"。

## 这张图在量什么

每次语义检索（你或系统拿一个问题去找记忆），都会在意思最近的几片街区各留一次到访记录。热图 = 窗口期内全部到访按「关键词簇 × 向量邻居区」统计的榜单。所以它的本质是**到访记录仪**，不是重要性仪表盘。

一行长这样：

```
jieba:考证 | emb:#671,674,678 ░░░░░░ 73 (0.1%) sim=0.44
```

从左到右：关键词｜这片簇住的几片向量邻居｜条形图｜7天内被点亮次数｜占总到访比例｜平均相似度。

## 四个口径，读数前先对表

1. **按行还是按次**。一次搜索会点亮几十条记忆——行数大 ≠ 被问得多。（历史注记：v2.5 时代这里写着"洒水车"——每晚一次全库扫描。R104/2026-10-09 照夜洗泥报告证伪：不是每晚一辆洒水车，是**每次 mcp_search 一整车**——旧代码把全部 sim>0.3 打分行整批入账后才按 limit 截断返回，账本记的是"打过分"不是"看见过"。96.6% 的行来自 ≥100 行的同秒洪水桶，桶大小只是跟着库长走。已于 R104 修复：入账按 limit*2 截断、与返回结果同口径；历史洪水桶整桶改标 `mcp_search_full`，统计排除，地层保留可查。）
2. **簇名口径 vs 记忆本体口径**。报告条目按簇名聚合。"簇从未被照亮"≠"记忆从未被照亮"——记忆本体可能以别的路径命中（`t1_prefetch` 等），只是没给那个簇名记分。
3. **时区**。日志存 UTC。看到"18 点洪峰"先加 8 换算成北京时间再判断是什么任务。
4. **_unclassified 不是垃圾场，是收货区**。没归上簇的行几乎全是前一晚刚写入的新记忆，等当晚 cluster 重建后归队。

## 来源分布：洪水退役之后

来源分布告诉你是谁在照亮记忆。历史（v2.4-v2.5 时代）：mcp_search 层按行数淹没一切——但那不是检索行为，是打分洪水的地层。R104（2026-10-09）之后：

- 现行 `mcp_search` 按「看见过」入账——与返回给调用方的结果同口径（limit*2 截断），一次搜索 ≈ limit*2 行，不再一整车。
- 历史洪水整桶改标 `mcp_search_full`，不删行、统计排除、地层可查。要研究"打分洪水的地层学"（比如照夜的洗泥报告），直接对这层 SELECT。

```
MCP搜索（手动）: 722行 ｜ 真实的「看见」事件
MCP搜索·洪水层: 624304行 ｜ 已退役地层，统计排除
T1语义检索（主动）: 20736行 ｜ 健康层，桶均~4行
```

按行算是历史的重量，按次算才是检索行为的世界。

## 从未被照亮名单

按簇名口径列出窗口期内零命中的簇（v2.5+ 按词频降序、封顶 50 个）。读法：它不是"死区清单"，是"还没被问过的街区"。黑区 ≠ 死区；从未照亮只说明没有一次搜索以它为最佳路径，不说明记忆不存在或不重要。

## 这张图不做什么

- 不判断重要性。灯亮的次数多，只说明被问得多。
- 不反映"今天发生了什么"。它照出的是**查询者的镜子**——深夜谁拿着手电在城里走，图上就是谁的形状。
- 不做遗忘依据。热图只记录，不裁决。
